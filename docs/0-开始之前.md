# 第 0 轮：开始之前，先聊聊 AI 和学习

这是一份开工前的说明，没有单独的项目作业。先知道我们想一起练什么，再去写第一行代码。

## AI 可以秒出代码，然后呢？

我们不对新同学的语言和框架做硬性要求。现在 AI 生成代码很快，但拿到代码之后，需求有没有理解对、方案能不能解决问题、结果能不能验证，仍然需要你自己判断。

项目需求可以很长，也可以只有一行。一句“做一个商城”，往下展开就会遇到很多问题：谁在用、要完成什么、哪些事情暂时不做、出错了怎么办。提示词的长短不是重点，能不能从已有信息继续找资料、提出问题、做出自己的设计，才是我们希望你练习的能力。

我们尤其看重两件事：

1. **信息搜集能力。** 能否找到相关资料，分辨来源是否可靠、版本是否适用，遇到相互矛盾的说法时继续查证。
2. **思考与设计能力。** 你如何理解问题、构思方案、做出取舍，以及怎样用实现和测试检查自己的判断。

## 面对一项新技术，先问三个问题

- 它到底是为了解决什么问题？这个问题在我的项目里存在吗？
- 它采用了什么技术方案？这套方案怎样发挥作用？
- 它带来了什么取舍？与其他方案相比，得到什么，又付出了什么？

技术广度让你知道有哪些路可以走，技术深度让你能把选中的路走明白。我们希望培养的是解决问题的能力，不是背出更多框架名，也不是让 AI 代替你完成所有判断。

可以让 AI 帮你整理资料、解释错误、提出替代方案和检查遗漏；它给出的结论要结合官方文档、源码或实际实验核验。保留关键资料、自己的决定和验证结果即可，不用整理一整本聊天记录。后续可以参考[用 AI 探索一个具体场景](架构阅读.md#借助-ai-探索一个场景)。

## 第一轮建议亲手写

第一轮是熟悉语法、代码、调试和测试的小任务，建议自己动手完成主要代码。可以查资料，也可以让 AI 解释报错、给提示或帮忙检查，但尽量先自己写一版，再比较不同写法。直接生成整套答案，会跳过这轮最值得练习的过程。

从第二轮开始，可以更充分地使用 AI 辅助开发。能否独立解释、修改、调试和验证自己的项目，始终是你的责任。

## 技术选型：优先尝试新版本

各轮列出的技术栈是推荐路线，可以根据问题选择其他语言与框架。**优先使用当前最新正式版，不以“老版本更稳”为默认理由停留在旧版本。** 只有关键依赖、工具或运行环境适配明显不足时，再调整版本，并说明具体问题。

Java 路线推荐 JDK 25 及以上、Spring Boot 4.x，开工时优先取最新正式版。2026-09-13 核验时，[JDK 最新正式版为 26](https://www.oracle.com/java/technologies/downloads/)，[Spring Boot 当前文档版本为 4.1.1](https://docs.spring.io/spring-boot/system-requirements.html)，后者支持 Java 26，使用 Spring Framework 7.x。这里说的“Spring 4”是 Spring Boot 4，不是旧版 Spring Framework 4。

其他语言、框架和工具也按同样原则选择。安装前查看发布页与适配说明，在项目中记录实际版本，让别人能复现你的环境；新版本发布后可继续升级并验证，不需要为了跟教程保持旧配置。

## 项目放在哪里

- **第一轮：** 由负责人在本仓库根目录的 [`work1/`](../work1/README.md) 统一收录，每位同学使用自己的 GitHub ID 作为子目录名。具体提交入口由负责人公布，无需为第一轮另建独立项目仓库。
- **第二轮起：** 自行创建独立的个人公开项目仓库。第二、第三、第四轮是同一个电商项目的持续迭代，在自己的仓库中维护，每轮保留 Git 标签或 Release；不把后续项目代码交到本仓库的 `work1/`。

准备好后，进入第一轮：[Java](1-基础语法-java.md) / [Go](1-基础语法-go.md)。遇到问题可以带着当前代码、查到的资料和尝试过程来聊，不用等到提交时才问。
