### 教学案例

使用以下两个请求贯穿讲解：

1. 创建 Todo：`POST /todos`
2. 查询单个 Todo：`GET /todos/{id}`

字段只使用：

- `id`
- `title`
- `completed`
- `ownerId`

不要自行增加标签、分页、缓存、消息队列等范围外功能。

### 必须讲清楚的内容

1. HTTP 方法、URL、路径参数、请求头、请求体、响应体、状态码和 JSON 分别是什么；
2. 创建成功、参数错误、未登录、无权限、资源不存在分别对应什么响应语义；
3. Controller/Handler、Service、Repository 各自负责什么；
4. 一次请求在三层之间如何流动；
5. 为什么 Controller/Handler 不应直接写 SQL；
6. 业务逻辑依赖 Repository 抽象、数据库实现依赖该抽象是什么意思；
7. 领域对象、请求 DTO、响应 DTO 和数据库记录为什么不必是同一个结构；
8. 三层分别怎样测试，以及哪些内容需要集成测试。

### 必须指出的边界

- Handler/Controller：处理协议输入输出，不承载持久化细节。
- Service：执行业务规则和用例编排，不依赖具体 HTTP 对象。
- Repository：表达业务需要的数据操作，不决定 HTTP 状态码。
- 数据库错误不能未经转换直接泄漏给客户端。
- “每层都创建接口”不是分层目标；接口应出现在需要隔离变化或测试替身的依赖边界。
- 分层不是要求所有请求机械经过大量空转方法。
