### 必须纠正的安全误区

1. 普通 Cookie 中直接保存 `userId` 不能作为可信登录凭据，因为客户端可以修改它。
2. 签名只保证完整性和来源校验，不保证内容保密；加密才解决机密性问题。
3. `HttpOnly` 降低 JavaScript 读取 Cookie 的风险，但不能消除所有 XSS 造成的操作风险。
4. `SameSite` 是 CSRF 缓解措施之一，不应被描述为所有部署条件下的完整替代方案。
5. Token 放入 Cookie 后，浏览器会自动携带它，因此必须重新分析 CSRF。
6. Token 放入 `Authorization` Header 通常需要应用代码主动读取和附加；其存储位置会改变 XSS 与泄漏风险。
7. HTTPS 保护传输过程，不会修复前端 XSS、日志泄漏或服务端密钥泄漏。
8. 密码不得明文保存，也不能使用普通快速哈希代替密码哈希算法。
9. 退出、过期和服务端立即撤销不是同一个概念。
10. Refresh Token 轮换、重用检测和吊销记录会重新引入服务端状态。

如果某条结论依赖浏览器、框架版本、同站/跨站部署或 CORS 配置，必须明确写出条件，不能使用绝对措辞。
