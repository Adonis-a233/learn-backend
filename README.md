# west2-online learn-backend 考核指南

这里是西二在线工作室后端方向（learn-backend）的考核指南，旨在为初学者提供一条循序渐进、语言无关的后端学习路线。

本考核不限定 Java、Go等具体语言。你可以选择一门适合长期维护后端服务的语言完成全部考核，但应在同一项目中保持主要技术栈稳定；更换语言前需说明原因和迁移范围。

## 概览

考核共四个阶段：一个起步任务和三轮电商项目。第一轮完成语言基础训练；第二轮通过数据库、TodoList、网页登录与 Docker 建立 Web 后端基础；第三轮完成下单闭环；第四轮补齐六个业务域，并围绕一个常见功能完成异步、重试、并发处理与压测实践。

具体任务、提交规则和答辩要求见 [考核文档导航](docs/README.md)。

| 阶段 | 学习内容 | 主要交付 | 预期时长 | 是否需要答辩 |
| --- | --- | --- | --- | --- |
| [第一轮：语言基础与赛事数据处理](docs/1-基础语法-java.md) | 基础语法、数据结构、异常处理、文件读写、测试、依赖管理 | 跳水赛事数据查询命令行程序 | 6 周 | × |
| [第二轮（电商第一轮）：数据库、TodoList 与网页登录](docs/2-电商基础.md) | MySQL、TodoList、网页登录与鉴权、Docker、测试与异常处理 | 可通过 Docker 运行、支持网页登录的 TodoList | 6 周 | √ |
| [第三轮：电商业务与下单闭环](docs/3-交易闭环.md) | 收货地址、类目、商品、SKU、购物车、订单与取消 | 从商品浏览到创建订单的完整功能链路 | 6 周 | √ |
| [第四轮：完整电商与工程实践](docs/4-完整电商与工程实践.md) | 六个业务域、异步与重试、并发、JUC、压测与单项深入 | 完整基础商城、一项深入功能及可复现的工程实践记录 | 按项目进度安排 | √ |

前三轮暂时各安排 6 周，共 18 周。这个安排要求学习者每周保持稳定投入，并由负责人根据基础和完成情况适当调整；零基础学习者如果未完成核心功能，应优先补齐当前轮次，不要为了赶时间直接进入下一轮。

## 作业提交

当届负责人统一发布的是报名、评审或汇总提交入口；这不替代学习者的项目仓库。学习者须按对应轮次要求自行创建项目仓库，并将公开仓库链接提交至负责人指定入口。

第一轮须由学习者自行创建一个公开 GitHub 仓库，并将完整的命令行项目提交到该仓库。第二轮起可在同一仓库持续迭代，也可按当届要求使用独立仓库或版本标签。建议结构如下：

```text
learn-backend-<github-id>/
├─round-1-diving-data/
└─ecommerce/
```

第二轮建立的用户域应在第三、第四轮继续使用；TodoList 保持独立模块，后续可以移除。各轮为关键阶段创建可追溯的 Git 标签或 Release。每次提交至少包含源代码、README、运行配置示例、数据库变更、测试和必要的设计图。禁止提交真实密钥、访问令牌、生产数据和无法公开的个人信息。

## 考核设计

| 名称 | 解释 |
| --- | --- |
| 参考资料 | 提供入门材料和官方文档入口，不代表唯一技术方案 |
| 知识点 | 本轮需要理解并能在代码或答辩中说明的内容 |
| 背景 | 用于解释业务场景、角色和问题边界 |
| 任务 | 必须交付的功能和工程内容 |
| 验收标准 | 判断本轮是否完成的可验证条件 |
| Bonus | 完成必做内容后再选择的深入功能或特性，不用于替代必做项 |
| 提示 | 对学习方法、常见错误和技术选择的补充说明 |

考核关注优先级依次为：正确性与安全性、可运行与可测试、业务建模、工程质量、性能与拓展。使用更新或更复杂的框架不会自动获得更高评价。

答辩重点检查：代码是否本人理解、关键设计为何这样选择、异常路径如何处理、测试如何证明结果，以及当前方案有哪些限制。允许使用 AI 辅助学习和开发，但必须标注主要使用场景，并能独立解释、修改和调试提交内容。

## 考核目标

我们的目标是帮助初学者建立一套完整的后端知识体系。完成全部考核后，你应当能够：

- 使用至少一门语言独立开发和维护后端服务；
- 把用户、商品、交易（含支付）、活动、仓储和履约六个业务域的需求转化为数据模型与接口；
- 使用数据库、缓存、消息队列和外部 API，并理解它们解决的问题和引入的成本；
- 为核心逻辑编写测试，定位常见故障，并依据数据完成一次性能或可靠性优化；
- 阅读官方文档和现有代码，清楚表达设计取舍，与客户端及其他后端开发者协作。

快速完成考核不等于满足企业后端工程师的全部要求。操作系统、计算机网络、数据库原理、数据结构与算法、安全、部署运维和源码阅读仍需要长期学习。本指南提供的是一条项目驱动的学习路径，不是技术清单，也不承诺仅凭完成考核即可达到特定岗位要求。

如果你计划把后端开发作为长期学习或工作方向，应认真完成每轮必做内容，并根据所选语言继续深入其运行时、并发模型、框架原理和工程生态。

## 项目结构

```text
.
├─docs/                         # 考核文档与参考资料
├─etc/                          # 通用规范、答辩说明和补充资料
│  └─blog/                      # 优质文章或学习笔记
├─img/                          # 文档图片与架构图
├─LICENSE
└─README.md
```

各语言的示例、脚手架和依赖说明应放在对应考核文档中，不单独复制一套考核标准。所有语言共享相同的业务目标和验收标准。

## 其他

本指南仅面向 learn-backend 后端方向，不再与 Android 方向绑定第一轮考核。不同语言在语法、生态和部署方式上存在差异，负责人可以补充语言相关提示，但不得降低通用的业务、测试和工程验收标准。

对第三方服务、云资源或付费 API 的使用必须提供免费、Mock 或本地替代方案，避免把付费能力和机器配置作为完成考核的前置条件。
