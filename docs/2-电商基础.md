# learn-backend 第二轮考核

> 本轮开始开发贯穿后续考核的电商项目。核心是完成用户域和商品域，并掌握数据库与 Web 后端框架的基本使用。

本轮支持 **Java** 和 **Go** 两条技术路线。Java 方向直接使用 Spring Boot，不要求先单独完成传统 Servlet/JSP 项目；但需要理解 HTTP、Servlet 容器和请求处理流程等基础概念。

## 任务

实现一个电商基础后端，完成用户域和商品域，并通过 HTTP API 对外提供服务。

本轮使用单体架构，不要求微服务。Java 方向建议直接从 Spring Boot 开始；不需要先实现一套传统 Java Web 项目再迁移到 Spring Boot。

### 1. 用户域

至少完成以下功能：

- 用户注册、登录；
- 获取和修改个人信息；
- 新增、查询、修改和删除自己的收货地址；
- 区分普通用户和管理员；
- 对需要登录的接口进行身份认证；
- 用户只能访问或修改属于自己的资料和地址。

基本要求：

- 密码不得明文或可逆加密存储；
- 用户名、邮箱等需要唯一的字段应有数据库约束；
- 登录失败时不得返回密码、散列值或内部异常堆栈；
- 不能只依靠前端隐藏按钮实现权限控制。

### 2. 商品域

至少完成以下功能：

- 商品类目的新增、修改、查询和停用；
- 商品的新增、修改、查询、上架和下架；
- 一个商品可以包含多个 SKU；
- SKU 可以拥有自己的规格、价格和基础库存；
- 普通用户可以分页浏览商品并查看详情；
- 管理员可以维护类目、商品和 SKU。

需要区分商品和 SKU。例如，一件衣服可以作为一个商品，不同颜色和尺码则属于不同 SKU。实际价格和基础库存应与 SKU 关联。

本轮库存只要求记录 SKU 的基础可售数量，不要求实现库存锁定、并发扣减、多仓、调拨和履约。

### 3. 数据库设计

- 使用 MySQL 保存业务数据；
- 根据用户域和商品域设计合理的表及关联关系；
- 使用主键、唯一约束、外键或其他明确的数据完整性方案；
- 金额不能直接使用会产生不可控误差的浮点类型；
- 价格、库存和购买数量等字段需要限制非法值；
- 避免无意义的字段重复和 `SELECT *`；
- 对列表查询提供分页，并为实际查询设计必要索引；
- 涉及多条相关记录的写入需要考虑事务。

需要提交数据库建表或迁移脚本。不能只提交数据库截图，也不能要求考核人员手工建表后才能启动项目。

### 4. 项目要求

- 使用 Java 或 Go 完成项目；
- Java 方向使用 Spring Boot，Go 方向使用成熟 Web 框架或标准库；
- 按用户、商品等业务职责组织代码，不能把全部逻辑写在 Controller 或 Handler 中；
- 对请求参数进行服务端校验，并提供统一、可理解的错误响应；
- 配置与代码分离，数据库密码、Token 密钥等不得写死或提交到仓库；
- 提供接口文档和项目结构说明；
- 编写自动化测试，覆盖主要成功路径和错误路径；
- 提供 README，说明环境、配置、数据库初始化、启动和测试方式。

### 5. 测试要求

至少覆盖以下场景：

- 注册、登录成功和失败；
- 重复用户名或邮箱；
- 未登录访问受保护接口；
- 普通用户访问管理员接口；
- 用户越权访问其他用户的资料或地址；
- 商品、SKU 和类目的正常维护；
- 商品下架后普通用户不能将其视为正常可售商品；
- 价格、库存等字段出现负数或非法值；
- 分页查询和数据库约束能够正常工作。

测试数量不是评分重点，关键业务规则和错误路径是否得到验证才是。

## Bonus

完成必做内容后，可以选择以下方向：

1. 实现购物车的添加、修改、删除和查询，为下一轮交易流程做准备；
2. 使用 Docker 或 Docker Compose 提供可复现的运行环境；
3. 为商品列表实现组合筛选、排序和稳定分页；
4. 记录管理员对商品、价格和库存的修改历史；
5. 自动生成并维护可交互的 API 文档；
6. 针对唯一约束或库存调整编写简单并发测试。

Bonus 不能替代用户域、商品域、数据库设计、权限和测试等必做内容。

## 提示

- 开始编码前，先画出用户、地址、类目、商品和 SKU 的关系；
- Java 方向可以直接学习 Spring Boot，不需要先完整学习 Servlet/JSP；
- 但需要理解一个请求如何经过 Web 容器、Controller、Service、数据访问层和数据库；
- MyBatis、GORM 等框架不能代替 SQL、数据库约束和事务设计；
- 密码应使用成熟的密码散列方案，不要自行设计加密算法；
- 金额可以使用定点十进制或最小货币单位整数；
- 先完成清晰、可运行的单体项目，再考虑缓存、消息队列和服务拆分；
- README 中应如实标注未完成内容和已知问题。
